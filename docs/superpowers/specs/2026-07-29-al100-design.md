# AL100 — Plataforma Inteligente de Recolección de Residuos Urbanos

## Design Document v1.0

**Fecha:** 2026-07-29
**Proyecto:** AL100
**Timeline:** 2 días (MVP para competencia)
**Target:** Santo Domingo → escalable a todo el país

---

## 1. Visión General

Plataforma que **previene** que la basura llegue a las calles mediante monitoreo GPS en tiempo real, predicción de generación de residuos por sector, y optimización del sistema de recolección. 4 módulos: Ciudadano, Chofer, Ayuntamiento, IA.

### Principios Arquitectónicos

- **Clean Architecture:** `domain/` → `application/` → `infrastructure/` → `interface/`
- **FastAPI como adaptador HTTP:** Sin lógica de negocio en los handlers
- **Supabase como proveedor externo:** Intercambiable por cualquier DB/Auth
- **IA Engine con puertos:** Hoy reglas determinísticas, mañana ML real — mismo contrato
- **Next.js RSC + CSR híbrido:** SSR para contenido estático, CSR para mapas interactivos
- **WebSocket (Supabase Realtime):** GPS tracking en vivo sin infraestructura extra

### Esquema SQL (PostgreSQL)

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT UNIQUE,
  role TEXT NOT NULL CHECK (role IN ('citizen', 'driver', 'admin')),
  code TEXT UNIQUE, -- código único para login (admin asigna)
  name TEXT NOT NULL,
  phone TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE sectors (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  geometry JSONB NOT NULL, -- GeoJSON polygon
  population_density FLOAT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE trucks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  plate TEXT,
  sector_id UUID REFERENCES sectors(id),
  driver_id UUID REFERENCES users(id),
  status TEXT DEFAULT 'available' CHECK (status IN ('available', 'on_route', 'maintenance')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE routes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  truck_id UUID REFERENCES trucks(id),
  driver_id UUID REFERENCES users(id),
  date DATE NOT NULL DEFAULT CURRENT_DATE,
  start_time TIMESTAMPTZ,
  end_time TIMESTAMPTZ,
  status TEXT DEFAULT 'pending' CHECK (status IN ('pending', 'active', 'completed', 'cancelled'))
);

CREATE TABLE gps_logs (
  id BIGSERIAL PRIMARY KEY,
  route_id UUID REFERENCES routes(id),
  latitude FLOAT NOT NULL,
  longitude FLOAT NOT NULL,
  timestamp TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE incidents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  type TEXT NOT NULL CHECK (type IN ('blocked_road', 'breakdown', 'trash_spill', 'overflow', 'other')),
  description TEXT,
  photo_url TEXT,
  location JSONB, -- {lat, lng}
  status TEXT DEFAULT 'reported' CHECK (status IN ('reported', 'in_progress', 'resolved')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE predictions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  sector_id UUID REFERENCES sectors(id),
  date DATE NOT NULL,
  predicted_volume FLOAT NOT NULL, -- kg or m³
  confidence FLOAT,
  recommendation TEXT, -- 'increase', 'decrease', 'maintain', 'extra_truck'
  factors JSONB, -- {holiday, weather, event, historical}
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(sector_id, date)
);

CREATE TABLE notifications (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  type TEXT NOT NULL,
  title TEXT NOT NULL,
  message TEXT NOT NULL,
  data JSONB, -- metadata adicional
  read BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_gps_route_time ON gps_logs(route_id, timestamp DESC);
CREATE INDEX idx_predictions_sector_date ON predictions(sector_id, date);
CREATE INDEX idx_notifications_user_read ON notifications(user_id, read);
CREATE INDEX idx_incidents_status ON incidents(status);
```

## 5. APIs REST

### Autenticación
```
POST   /api/auth/register     Admin crea cuenta (body: {name, role, code})

GET    /api/auth/me           Perfil del usuario autenticado
```

### Rutas y GPS
```
GET    /api/routes/active     Ruta activa del chofer autenticado
POST   /api/routes/start      Iniciar ruta (body: {truck_id})
POST   /api/routes/{id}/end   Finalizar ruta
GET    /api/routes/{id}       Detalle de ruta + últimos GPS logs
```

### Camiones
```
GET    /api/trucks            Listar camiones (admin)
GET    /api/trucks/{id}       Detalle camión
GET    /api/trucks/{id}/location  Última ubicación GPS
```

### Sectores
```
GET    /api/sectors           Listar sectores
GET    /api/sectors/{id}      Detalle sector + última predicción
```

### Incidencias
```
POST   /api/incidents         Reportar incidencia (auth: citizen, driver)
GET    /api/incidents         Listar incidencias (filtro por status/tipo)
PUT    /api/incidents/{id}    Actualizar estado (admin)
```

### Dashboard (Admin)
```
GET    /api/admin/stats       Estadísticas generales

GET    /api/admin/users       CRUD usuarios

```

## 6. Eventos en Tiempo Real (Supabase Realtime)

| Channel | Publicante | Suscriptores | Payload |
|---------|-----------|--------------|---------|
| `gps:{route_id}` | Chofer (cada 3s) | Ciudadano, Admin | `{lat, lng, timestamp, speed}` |
| `notifications:{user_id}` | Backend | Usuario destino | `{type, title, message}` |
| `alerts:admin` | Backend | Admin dashboard | `{type, severity, message}` |
| `route:{route_id}:status` | Backend | Admin | `{status, driver_name, truck}` |

**Flujo GPS:**
1. Chofer inicia ruta → `POST /api/routes/start`
2. Web del chofer captura coordenadas vía Geolocation API
3. Envía a Supabase Realtime channel `gps:{route_id}`
4. Ciudadano suscrito al canal recibe update → mueve marker en Mapbox
5. Dashboard admin actualiza mapa simultáneamente

**Flujo Notificaciones:**
1. Backend predice hora de llegada
2. Inserta en tabla `notifications`
3. Supabase Realtime emite al channel del usuario
4. Web Push API envía notificación al navegador (si está cerrado)

## 8. Estrategia de IA

### MVP: Reglas Determinísticas (Rules Engine)

```
┌──────────────┐     ┌──────────────────┐     ┌────────────────┐
│  Prediction  │────>│  IA Engine       │────>│  Rules Engine  │
│  Controller  │     │  (Application)   │     │  (Infrastructure)│
└──────────────┘     └──────────────────┘     └────────────────┘
                           │                          │
                      ┌────▼────┐             ┌──────▼──────┐
                      │ IPredictionPort       │  Futuro:    │
                      │ (interface)           │  ML Model   │
                      └─────────┘             │  Adapter    │
                                               └─────────────┘
```

**Reglas del MVP:**
- Día festivo → +40% volumen estimado
- Sector comercial → +50% sobre residencial
- Lluvia (weather API) → -20% (menos actividad en calles) / +30% (residuos arrastrados)
- Evento en sector → +100% volumen (factor desde calendario)
- Fin de semana → +25% residencial
- Promedio histórico → baseline de cada sector

**Output de predicción:**
```json
{
  "sector_id": "uuid",
  "date": "2026-08-15",
  "predicted_volume": 4500.0,
  "confidence": 0.85,
  "recommendation": "increase_frequency",
  "factors": {
    "base_volume": 3000.0,
    "holiday_multiplier": 1.4,
    "weather_multiplier": 1.0,
    "event_multiplier": 1.0,
    "day_of_week_multiplier": 1.1,
    "total": 1.5
  }
}
```

### Futuro: ML Real
- Mismo puerto `IPredictionPort`
- Nuevo adaptador con Scikit-learn / XGBoost
- Datos históricos de `gps_logs`, `routes`, `incidents`, weather
- Modelo de serie temporal (Prophet / LSTM)

## 11. Estrategia de Seguridad

- **Auth:** Supabase Auth con Row Level Security (RLS)
- **RLS Policies:** Ciudadano ve solo sus datos y camiones de su sector
- **API Keys:** Mapbox token con URL restrictions
- **CORS:** Solo origen de Vercel
- **Rate Limiting:** FastAPI middleware (slowapi)
- **Validación:** Pydantic (backend) + Zod (frontend)
- **SQL Injection:** SQLAlchemy parametrizado
- **XSS:** Next.js sanitiza output por defecto

### Row Level Security (Supabase)

```sql
-- Choferes solo ven su ruta activa
CREATE POLICY driver_own_route ON routes
  FOR ALL USING (driver_id = auth.uid());

-- Ciudadanos ven camiones de su sector
CREATE POLICY citizen_sector_trucks ON trucks
  FOR SELECT USING (
    sector_id IN (
      SELECT sector_id FROM user_sectors WHERE user_id = auth.uid()
    )
  );

-- Admin ve todo
CREATE POLICY admin_all ON trucks
  FOR ALL USING (
    auth.jwt() ->> 'role' = 'admin'
  );
```

| 2 días insuficiente | Alta | Crítico | Priorizar funcionalidad core sobre features extra |
| Sin datos históricos reales | Alta | Medio | Datos sintéticos + IA con reglas |
| Web Push no soportado | Baja | Bajo | Notificaciones in-app como fallback |
